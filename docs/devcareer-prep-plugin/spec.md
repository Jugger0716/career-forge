# 실행 스펙 — DevCareer Prep (devcareer-prep)

> `/harness` Plan 세그먼트(multi 모드, 페르소나 3인 병렬 제안 → 합성)가 산출한 구조화 스펙을
> 오케스트레이터가 렌더링한 문서다. 사용자 원문 요구사항은 `SPEC_INPUT.md` 참조.

**한 줄 요약**: 22개 수용 기준, 25개 엣지 케이스 — 결정적 증거 원장 + Layer 1 검증 하네스를 스킬보다 먼저 세우는 12단계 MVP 스펙

### 목표

Git 히스토리를 결정적 스크립트로 수집해 만든 "증거 원장(evidence ledger)"을 유일한 사실 원천으로 삼고, 그 위에 경력 기술서 → 지식맵 → 갭 리포트를 단방향 계층으로 쌓는 Claude Code 플러그인(devcareer-prep)의 MVP를 그린필드 레포 `career-forge`에 신규 구축한다. 모든 인용의 실재성은 LLM이 아니라 스크립트가 검증하며, 이 프로젝트 최초의 Layer 1 기계 검증(스키마·frontmatter·인용 무결성·negative 픽스처·픽스처 회귀)을 기능보다 먼저 세운다.

### 배경

`C:/workspace/career-forge`는 `.gitignore` 1커밋뿐인 완전한 빈 레포다. 기존 코드 패턴이 0이므로 이번 설계는 "기존 구조에 맞추기"가 아니라 "3주간 깨지지 않을 계층 경계를 처음부터 못 박기"가 전부다.

세 전문가가 독립적으로 같은 결론에 도달했다: 이 프로젝트의 진짜 난이도는 마크다운 작성이 아니라 (1) git 히스토리 볼륨을 컨텍스트에 넣는 문제와 (2) "출처 인용 강제" 규약을 LLM이 아니라 기계로 강제하는 문제다.

원 SPEC은 GitExtractor를 LLM 에이전트로, FactChecker도 LLM으로 두었는데 이 구조에서는 커밋 해시 자체가 생성물이 되어 "그럴듯한 40자 hex"를 지어내도 아무도 잡지 못한다 — 겉보기 산출물은 완벽해 보이는 조용한 실패이며, 할루시네이션 방지라는 이 제품의 핵심 가치를 통째로 무력화한다.

볼륨 문제는 실측으로 확인됐다: `C:/workspace/pass-api-be` 134커밋의 `git log --numstat` 메타데이터만 51KB, 커밋당 평균 diff는 약 10KB로 100커밋 full diff는 25만 토큰 규모다. 또한 같은 레포에서 `--all`은 325커밋, HEAD는 134커밋, 머지 제외 97커밋, 그중 사용자 본인 커밋은 9개뿐이었다 — 범위·저자 선택 하나로 '경력'의 분량이 통째로 바뀐다.

이 레포는 build/test/lint가 전무해 harness Layer 1(기계 검증)이 비활성 상태이며, 완료 판정이 전적으로 LLM 판단과 주관적 성공 기준("이 정도면 쓸 수 있다")에 의존한다. 검증 하네스를 스킬보다 먼저 만들지 않으면 Phase 2~4 내내 "스키마가 실제로 지켜지는지 아무도 모르는" 부채가 누적된다.

플랫폼은 Windows 11 / PowerShell 7이며, 이 머신은 `core.quotepath`와 `i18n.logOutputEncoding`이 미설정이라 한글 파일명이 옥탈 이스케이프로 출력된다 — 한국어 사용자 레포에서 확실히 터진다. 로컬 레퍼런스 구현(agent-harness 8.9.0, superpowers 6.3.0)이 마크다운 중심 플러그인의 기계 검증·CRLF 방어·Windows 훅 래퍼 패턴을 이미 실증해 두었으므로 새로 발명하지 않고 그대로 차용한다.

git의 실제 출력 계약도 실측으로 확인됐다(git 2.47.0.windows.2, 픽스처 레포 직접 생성). 삭제 커밋에서 `git cat-file -e <sha>:<deleted-path>`는 `fatal: path ... does not exist`와 함께 **exit 128**을 반환하는데, 같은 커밋의 `git log --numstat`은 그 경로를 정확히 보고한다 — 즉 원장이 스스로 생성한 (해시, 경로) 쌍이 자기 검증기에서 FAIL 나는 자기모순이 존재한다. 또한 `--numstat`은 리네임을 `src/{old => new}/m.txt` 같은 축약형으로 내보내며, 같은 커밋에 `-z`를 붙이면 `0\t0\t\0src/old/m.txt\0src/new/m.txt\0`로 두 경로가 분리돼 나온다. 이 두 사실은 L0 수집기·검증기의 git 호출 계약을 스키마 확정 이전에 못 박아야 하는 근거다.

### 접근 방식

## 1. 핵심 아키텍처 결정: 사실과 산문의 경계를 파일 시스템에 새긴다

**GitExtractor는 에이전트가 아니라 결정적 스크립트다.** 세 전문가 전원 합의 사항이며 이번 설계에서 SPEC을 수정하는 유일한 지점이다. 고정 포맷 git 명령의 출력을 파싱하는 데 LLM 추론은 필요 없고, LLM을 쓰는 순간 해시 할루시네이션 경로가 열린다. `scripts/collect-git-facts.mjs`가 `evidence.json`(증거 원장)을 만들고, 이후 모든 LLM은 해시를 **쓰지 않고 원장 항목 ID를 고르기만** 한다. 이 규칙 하나로 해시 할루시네이션이 구조적으로 불가능해진다.

**정본은 JSON, 마크다운은 렌더된 뷰다.** `career.json` / `knowledge-map.json` / `gap-report.json` / `plan.json`을 JSON Schema로 정의하고 사용자 대면 `.md`는 `scripts/render-markdown.mjs`의 출력물로만 생성한다. 마크다운을 에이전트 간 계약으로 쓰면 검증 불가능한 산문 계약이 되어 파이프라인 전체가 취약해진다. "출처 인용"이 산문 속 관행이 아니라 `evidence[]` 타입 필드가 되면서 FactChecker의 절반이 LLM 판정에서 스크립트 검증으로 내려온다.

**단방향 6계층 + ID 참조.** L0 git 증거(불변) → L1 경력 → L2 지식맵 → L3 갭 → L4 커리큘럼/문제 → L5 채점. 상위는 하위의 ID만 참조하고 역참조를 금지한다. 이 제약이 "생성된 코테 문제가 실제 경력과 논리적으로 연결될 것"이라는 성공 기준을 문서화된 바람이 아니라 **스키마 제약**으로 바꾼다.

## 2. 2단 팩트체크

- **1단(기계, 저비용, 결정적)**: 산출물의 모든 인용에 대해 (a) 원장에 존재하며 `excluded !== true`이고 `authorEmail`이 config.json에 저장된 선택 identity 집합에 속하는가, (b) 커밋 객체가 `git rev-parse --verify --quiet <sha>^{commit}`로 실존하는가, (c) 인용된 (해시, 경로) 쌍이 **그 커밋의 diff에 등장하는가**를 검사한다. (b)는 (c)의 선검사이며, (b)를 통과한 해시에 대해서만 (c)를 호출해 `bad object` 128 경로 자체를 없앤다. (c)는 커밋 트리 조회가 아니라 `git show --numstat --format= -z <sha>` 결과 집합과의 대조로 판정한다 — 삭제 커밋의 트리에는 그 경로가 없어 `git cat-file -e <sha>:<path>`가 exit 128로 실패하므로, 트리 조회를 경로 실존성의 축으로 쓰면 "레거시 모듈을 제거했다" 같은 **참인 주장이 통째로 오탐**된다(리네임 이전 경로도 동일). `git cat-file -e <sha>:<path>`는 파일 내용을 인용하는 옵트인 스니펫에 한해 추가 확인용으로만 쓰고, 원장의 `changeType`이 `D`이거나 `oldPath` 계열 항목에는 적용하지 않는다. **머지 커밋 M의 변경 집합은 수집기와 검증기가 동일한 연산 —「M의 변경 집합 = `git diff --numstat -z M^1 M`」(= `git show --numstat --format= -z M`, 실측 동치) — 으로 계산하며 `scripts/lib/git.mjs`에 단일 구현한다. 이는 diff 기준일 뿐이며 커밋 순회에는 `--first-parent`를 쓰지 않으며 순회 범위는 HEAD/`--all`(과 since/until)만으로 결정한다** — 순회에 `--first-parent`를 쓰면 사이드 브랜치 커밋이 통째로 사라진다. **머지 '제외'는 순회 제외가 아니라 원장 등재 후 `excluded: true` 표시를 뜻한다** — 머지 커밋은 두 설정 모두에서 원장에 등재되고 `files[]`도 두 설정 모두에서 1부모 diff로 채워진다(AC-9가 전제하는 '제외 커밋도 원장에 남는다'와 동일 의미론). 즉 머지 포함 여부는 순회 결정 인자가 아니라 `excluded` 플래그와 정량 집계 반영 여부를 결정하는 값이다. `git log --numstat`은 머지에 대해 빈 출력을, `git show --numstat`은 1부모 대비 변경 전량을 내보내므로 규칙을 통일하지 않으면 원장에 없는 (머지해시, 경로) 쌍이 (c)를 통과한다. `files[]`는 **머지 포함/제외와 무관하게 항상 1부모 diff로 채우고, 제외 설정에서는 해당 커밋에 `excluded: true`만 표시한다** — 그래야 수집기 집합과 검증기 집합의 동치가 설정에 관계없이 항상 성립한다. 다만 1부모 diff는 곧 '머지된 브랜치가 가져온 변경 전량'이므로 그렇게 유입된 항목에는 `viaMerge: true`를 부여해 **항목 단위 집계와 커밋 레벨 `insertions`/`deletions` 양쪽의 정량 집계에서 제외하며(커밋 레벨 값은 `viaMerge !== true`·`binary !== true` 항목의 합이므로 머지 커밋에서는 항상 0이다)**, **머지 해시 인용은 `basis: commit`(정량 주장)의 근거로 쓸 수 없으며 `inference`만 허용한다 — 정량 주장이 머지 해시를 인용하면 FAIL이다.** 사용자가 머지를 제외하면 검증기는 머지 해시 인용을 (a)축에서 무조건 FAIL 처리한다. `scripts/verify-evidence.mjs`가 담당하며 LLM 호출 0회.
- **모든 git 호출은 (exit code, stderr 패턴) 쌍으로 3분류한다**: `0`=OK, `1`=조회 실패(인용 FAIL로 집계), exit 128이라도 stderr가 `bad object` / `unknown revision` / `Needed a single revision` / `does not exist in` 패턴에 걸리면 **조회 실패로 보아 인용 FAIL로 집계**하고, 그 외 128과 129 이상만 **도구·레포 오류로 별도 리포트하며 인용 FAIL로 집계하지 않는다.** exit code 단독으로 분류하면 (b)축이 죽은 검사가 된다 — `git rev-parse --verify <sha>^{commit}`는 존재하지 않는 객체에 대해 exit 1이 아니라 exit 128을 반환하므로, 128을 일괄 '도구 오류'로 빼면 AC-8이 결정적 100% 탐지를 요구하는 가짜 해시 케이스가 인용 FAIL로 집계되지 않는다((b)축에 `--quiet`를 붙이면 조회 실패가 exit 1로 정규화되어 이 예외 목록에 의존하지 않는다). 반대로 non-zero를 일괄 FAIL로 처리하면 git 실행 자체가 깨진 상황이 '인용 전부 허위'로 보고되어 AC-7의 실존율·AC-8의 탐지율 측정이 무의미해진다.
- **2단(LLM, 상위 티어)**: "이 커밋이 정말 그 주장을 뒷받침하는가"라는 의미 판정만. 프롬프트는 "검증하라"가 아니라 **"반증하라"**로 적대적으로 작성하고, 생성 측의 추론 과정을 입력에서 제외해 독립성을 확보한다.

전역 모델 라우팅 규약(수집=저티어, 판정=상위티어)과 정확히 일치한다. 각 템플릿 상단에 의도 티어를 명시하고, 오케스트레이터가 세션 모델을 상속시키지 않도록 SKILL.md에 명문화한다.

## 3. 근거 등급과 REJECT 정책

주장 유형별로 근거 등급을 스키마 수준에서 분리한다: `commit`(해시 필수) / `inference`(근거 커밋 나열 + 추론임을 명시) / `external`(allow-list 내 URL 필수) / `insufficient`(근거 부족 배지). 정량 주장(기간·커밋 수·파일·라인)만 해시를 강제하고 역할·기여 서술은 `inference`로 분리해야 "커밋 나열로 퇴화"와 "규약 붕괴" 두 실패 모드를 동시에 피한다.

**"승인 없으면 출력 금지"는 문서 전면 차단이 아니라 항목 단위 강등으로 해석한다.** 재생성 최대 2회 → 이후 해당 항목을 삭제하지 말고 `근거 부족 - 미검증` 배지로 남겨 출력한다. 아무것도 출력하지 않는 경로는 금지한다. 그대로 구현하면 재시도 루프에 갇혀 사용자가 빈손이 되는 최악의 UX가 발생한다.

## 4. 볼륨·범위 통제

L0 추출 계약에 예산 상한을 두되 **P0의 예산 축은 `max_commits` 하나로 고정한다**(바이트 상한·파일 수 상한은 P1로 연기 — 선택 예산 K가 `max_commits`로만 산정되므로 다른 예산 축을 P0에 남기면 "절단됐다고 선언하면서 누락 0건"인 자기모순 값이 생긴다). **상한 초과를 예외가 아니라 일급 출력 필드**(`truncated: {reason, dropped_commits}`, `coverage: {analyzed, total, period, exclusions, samplingMethod}`)로 다룬다. 조용한 절단을 구조적으로 불가능하게 만든다. 상한 초과 시 절단이 아니라 **구현 5단계에 리터럴로 고정된 정본 `samplingMethod` 규칙에 따른 명시적 샘플링**을 쓰고 기준을 문서에 못 박아 재현성을 확보한다(규칙은 여기서 재서술하지 않고 그 리터럴을 참조한다).

`truncated`는 evidence 공통 필드로 스키마에 명시하고, 샘플링 규칙의 **정확성과 결정성**을 300커밋 대량 픽스처에서 골든 비교로 검증한다(AC-21). 이 게이트가 없으면 구현자가 `slice(0, max)`로 자르고 `truncated.reason`만 채워도 전 AC가 통과하며, 사용자는 최근 커밋만 반영된 결과를 전체 분석으로 믿는다.

`--no-diff` 모드(파일 경로·통계만 사용, diff 원문 미전송)를 P0 기본값으로 둔다. 사내 레포 첫 실행의 심리적 진입 장벽과 컨텍스트 폭발을 동시에 해결한다.

## 5. 저자 정체성 게이트

첫 인터랙션에서 `git shortlog -sne` 결과를 제시하고 사용자가 자기 identity를 **다중 선택**하게 한다(추측 금지). 동시에 HEAD/`--all`, 머지 커밋 포함 여부, 기간을 확정하고 그 결정을 산출물 최상단에 기록한다. **머지 포함을 선택하면 머지가 가져온 타 저자 변경이 사용자 커밋에 귀속된다는 점을 이 시점에 고지하고**, 그 항목들은 `viaMerge: true`로 표시돼 정량 집계에서 제외되며 머지 해시로는 정량 주장을 세울 수 없음을 함께 안내한다. 봇 패턴(`[bot]`, dependabot, github-actions)과 vendored 경로(node_modules/dist/vendor/*.lock/migrations)를 기본 제외하되 조정 가능하게 한다. 이 게이트 없이는 어떤 인용 검증도 무의미하며, 남의 성과를 자기 경력으로 기술하는 실질 피해가 발생한다.

## 6. 안전·프라이버시

**저장 루트 정본은 하나다: `~/.devcareer/<repo-key>/`.** 산출물(career/knowledge-map/gap-report/plan JSON과 그 렌더 마크다운)뿐 아니라 **원장 `evidence.json`과 상태·설정 파일 `state.json`·`config.json`도 모두 이 루트 아래에 쓴다** — 루트가 둘로 갈리면 스테일 판정(AC-22)과 identity 집합 조회(AC-7 (a)축)가 서로 다른 파일을 정본으로 삼는다. **`.devcareer`는 저장 루트가 아니라 디렉터리 이름 상수이며(§9), 대상 레포 내부 `<repo>/.devcareer/`는 사용자 명시 동의가 있을 때만 저장 루트로 전환된다** — 전환 시에는 그 실행의 파일 전부가 함께 레포 내부로 가고(홈·레포에 나눠 쓰지 않는다) 동시에 해당 레포 `.gitignore`에 항목 추가를 제안한다. 이 플러그인은 사용자가 소유하지 않은 사내 레포에서 실행되는 것이 명백하므로, 남의 레포 오염과 개인 경력 정보·동료 PII의 공개 레포 커밋 사고를 막는 가장 싼 방어다.

**`<repo-key>` 산출 규칙(결정적 — `scripts/lib/store.mjs`의 단일 함수만 수행한다).** 이 값은 저장 루트의 두 번째 경로 요소이므로 규칙이 없으면 store.mjs가 루트를 결정할 수 없고, 같은 레포가 표기만 다른 절대경로로 지정될 때마다 산출물이 다른 디렉터리로 흩어져 스테일 판정(AC-22)과 identity 집합 조회(AC-7 (a)축)가 매번 빈 파일을 읽는다. 다음 네 단계로 고정한다.

1. **입력 정본화** — 사용자가 넘긴 문자열이 아니라 `git -C <repo> rev-parse --show-toplevel`의 출력을 입력으로 쓴다. 상대 경로(`.`, `..`), 심볼릭 링크, 레포 하위 디렉터리 지정이 여기서 한 번에 해소되므로 정규화가 떠안을 경우의 수가 줄어든다(비-git 경로는 애초에 실행 대상이 아니므로 이 규칙을 적용하지 않는다).
2. **정규화(순서 고정)** — (i) 유니코드 NFC 정규화, (ii) `\\?\` / `\\?\UNC\` 확장 길이 접두사 제거, (iii) 모든 백슬래시를 `/`로 치환, (iv) 연속 슬래시를 하나로 축약(단 UNC를 뜻하는 선행 `//`는 보존), (v) 후행 `/` 제거(드라이브 루트 `c:/`는 예외로 보존), (vi) 대소문자 비구분 플랫폼(Windows)에서는 경로 전체를 ASCII 소문자로 폴드하고 대소문자 구분 플랫폼(POSIX)에서는 케이스를 보존한다 — 드라이브 문자는 (vi)에 의해 Windows에서 항상 소문자가 된다. 이로써 `C:\Users\me\Repo`, `c:/users/me/repo/`, `\\?\C:\Users\me\Repo`, 그리고 그 레포의 하위 디렉터리를 넘긴 경우가 모두 같은 정규화 문자열로 수렴한다.
3. **키 조립** — `<slug>-<hash8>` 형식이다. `slug`는 정규화 경로의 마지막 요소를 ASCII 소문자로 낮추고 `[^a-z0-9]+`를 `-`로 치환한 뒤 앞뒤 `-`를 떼고 32자로 자른 값이며(결과가 빈 문자열이면 `repo`), `hash8`은 정규화 경로의 UTF-8 바이트에 대한 SHA-256 hex의 앞 8자다(`node:crypto`만 사용해 의존성 0을 유지한다). **slug는 사람이 디렉터리를 알아보기 위한 장식일 뿐이고 레포 동일성 판정은 전적으로 해시가 한다** — 한글 레포명은 slug가 `repo`로 축약되지만 해시는 정확히 구분된다.
4. **충돌 처리** — 각 `<repo-key>/` 디렉터리에 정규화 경로의 SHA-256 **전체 64자 hex**만 담은 `.repo-key` 파일을 함께 쓴다(절대경로 원문은 쓰지 않는다 — AC-15의 '산출물에 로컬 절대경로를 남기지 않는다'와 정합). 키 생성 시 대상 디렉터리가 이미 존재하는데 그 `.repo-key` 값이 지금 계산한 64자 hex와 다르면 `hash8`의 자릿수를 8 → 12 → 16 → … → 64로 4자씩 늘려 같은 절차를 반복하고, 처음으로 비어 있거나 값이 일치하는 디렉터리를 그 레포의 키로 확정한다. 확장 순서가 고정이므로 같은 입력은 언제나 같은 키에 도달한다(충돌 시에도 결정적이다).

코드 원문 인용은 기본 비활성(경로 + 해시 + 요약만), 원문 인용은 옵트인. diff 인용 경로에 시크릿/PII 마스킹(AWS 키, `-----BEGIN ... PRIVATE KEY-----`, JWT, `password=`, 이메일 패턴)을 삽입한다.

**원장에 남기는 것과 밖으로 흘러나가는 것을 분리한다(제외 커밋 PII).** `excluded: true` 커밋은 예산과 무관하게 **원장에 전량 등재한다** — AC-7 (a)축·AC-9·AC-6 (i)(ii)(iii)·AC-7 집합 동치의 관측 가능성이 여기 걸려 있으므로 이 등재 자체를 프라이버시 이유로 되돌리지 않는다. 그러나 그 관측 가능성이 실제로 요구하는 필드는 `id`·`hash`·`shortHash`·`parents`·`isMerge`·`authorDate`·`insertions`·`deletions`·`files[]`·`excluded`·`exclusionReason`이며, **`authorEmail`·`subject`·`coAuthors` 세 필드를 읽는 검사는 하나도 없다**(검증기는 `excluded` 판정에서 먼저 종료되므로 제외 커밋의 저자 대조에 도달하지 않는다). 따라서 이 세 필드는 **기록 시점에 축소한다** — `authorEmail: null`, `subject: null`, `coAuthors: []`. 사후 마스킹이 아니라 미기록이다: 마스킹은 알려진 패턴만 가리는데 동료의 이메일과 커밋 제목 자체는 알려진 패턴이 아니므로 그대로 남는다. 축소는 `evidence.schema.json`이 `excluded` 값에 따른 조건부 제약(`allOf`의 `if`/`then`)으로 강제하며 위반 원장은 `--schema-check`에서 FAIL 한다. `excluded: false` 커밋에서는 세 필드가 종전대로 필수이고 `authorEmail`은 `format: email`을 유지한다.

**남는 것의 잔여 위험을 숨기지 않는다.** 축소 후에도 제외 커밋의 `files[].path`와 `authorDate`는 원장에 남는다(각각 AC-7 (e)축 집합 동치와 순회 재현에 필요하다) — 이 두 값은 동료의 담당 영역과 활동 시각을 드러낸다. 그러므로 **원장 파일 자체를 LLM 컨텍스트에 통째로 넣지 않는다**: 상위 계층(L1+) 스킬은 원장 원본이 아니라 `excluded: false` 커밋만 담은 **투영본**을 읽으며, 그 투영은 스킬이 임의로 수행하지 않고 **구현 7단계 (f)가 지정한 단일 함수**(`scripts/lib/store.mjs`의 `projectLedgerForSkills(evidence)`)가 수행한다. 다만 투영은 **보조 방어**임을 명시한다 — 스킬이 원장을 직접 읽는 것을 결정적으로 막을 수단이 없으므로, 실제 방어는 위의 기록 시점 축소다. `--all-identities`는 `author-not-selected` 축만 무력화하므로 **타 저자의 비-봇·기간 내 커밋이 `excluded: false`가 되어 이메일·제목이 평문으로 기록된다**(봇·기간 밖·머지 제외·shallow 경계분은 `excluded: true`로 남아 축소가 그대로 적용된다 — 축소가 통째로 꺼지는 것이 아니라 가장 중요한 축 하나가 꺼진다) — 이 플래그를 탐색·테스트 전용으로 한정한 §5 규약이 프라이버시 규약이기도 하다. 대상 레포에서 저자 목록을 재도출해(`git log --all --format=%ae`) 선택 identity를 뺀 deny-list로 산출물을 스캔하는 방어도 검토했으나, 오탐 특성(사용자가 여러 identity를 가진 경우 등)과 대형 레포에서의 비용이 측정되지 않아 **P0에서는 채택하지 않고 미해결 항목으로 남긴다** — 채택한다면 소유 파일을 함께 지정해야 한다.

## 7. 구조·플랫폼

**skills 중심 단일 표면.** 로컬 레퍼런스인 agent-harness 8.9.0은 `agents/`도 `commands/`도 없이 skills 단일 표면 + `templates/*.md` + 모델 티어 맵으로 구성된다. SPEC의 skills/agents/commands 3중 구조는 같은 5개 역할을 세 번 선언하는 중복이므로, SKILL.md를 슬래시 명령 겸 진입점으로 쓰고 내부 역할(GitExtractor·CareerWriter·KnowledgeMapper·FactChecker·CurriculumDesigner)은 orchestrator가 명시 디스패치하는 `templates/*.md`로 둔다. `agents/*.md` 정적 정의는 Claude가 임의 시점에 자동 호출할 수 있어 "검증 없이는 출력 금지" 게이트를 우회시킨다.

**슬래시 명령 접두사는 설계로 고를 수 있는 값이 아니다.** 콜론 접두사는 `.claude-plugin/plugin.json`의 `name` 값에서 자동 파생되며 임의 문자열로 선언할 지점이 존재하지 않는다(로컬 실측: `"name": "agent-harness"` → `agent-harness:codebase-audit`, `"name": "superpowers"` → `superpowers:brainstorming`. 공식 `plugin-dev` 문서도 `name`의 용도로 "Command namespacing"을 명시한다). 따라서 §9가 플러그인 이름을 `devcareer-prep`으로 확정한 이상 **정본 접두사는 `devcareer-prep:`**이고 명령은 `/devcareer-prep:career-from-git`, `/devcareer-prep:skill-gap`, `/devcareer-prep:prep-plan`이다. 임의 접두사(`dcp:` 등)를 문서에 적으면 스펙에 적힌 명령이 하나도 존재하지 않게 되며, 그 증상이 바로 아래에서 지목한 "아무 일도 안 일어남"이다.

충돌 회피의 실효 수단은 접두사가 아니라 **3인칭 description + 고유 트리거 어휘**(`경력 기술서`, `DevCareer`)와 배포 전 라우팅 테스트다. `/grade`·`/prep-plan` 같은 일반 명칭은 이미 설치된 `/study`·`/codebase-audit` 등과 충돌 확률이 높고, 충돌 증상이 "아무 일도 안 일어남"이라 진단이 매우 어렵다. 문서·README·SKILL.md에 등장하는 접두사 표기가 plugin.json `name`과 문자열 일치하는지는 validate-plugin이 기계 검사한다(AC-18).

**git 호출은 셸 문자열 조합이 아니라 인자 배열로**, 고정 프리픽스 `git -C <repo> --no-pager -c core.quotepath=false -c i18n.logOutputEncoding=UTF-8`를 강제한다. **모든 `--numstat` / `--name-status` 호출에는 `-z`를 붙여 NUL 구분 출력을 파싱한다** — `core.quotepath=false`는 유니코드 옥탈 이스케이프만 끌 뿐 리네임 축약형(`a => b`, `src/{old => new}/m.txt`)과 특수문자 경로를 해결하지 못한다. `-z` 없이 파싱하면 원장 `files[]`에 실재하지 않는 경로 문자열이 들어가 인용 검증이 전량 실패하고, 존재하지 않는 디렉터리(`{old`)가 모듈로 잡혀 경로→모듈 매핑·확장자 히스토그램·최다 변경 파일 집계가 오염된다. §4가 `--no-diff`를 P0 기본값으로 두므로 numstat은 우회로가 아니라 **주 경로**다.

PowerShell에서 사용자 입력을 `Invoke-Expression`에 넣는 패턴은 금지 규칙으로 문서화한다. `.gitattributes` + **워킹 트리 CR 검사 스크립트**를 둘 다 둔다(`.gitattributes`는 스테이징 시 정규화만 해서 워킹 트리를 보호하지 못한다 — 참조 플러그인이 CRLF로 기능이 조용히 죽는 사고를 실제로 겪었다).

## 8. 범위 축소와 일정

MVP P0 = `/devcareer-prep:career-from-git` + `/devcareer-prep:skill-gap`(자가진단 입력만, 퀴즈 없음). `/devcareer-prep:prep-plan`은 Phase 3, `/devcareer-prep:grade`는 P2로 내린다. 앞의 두 기능이 먼저 "쓸 만해"지지 않으면 뒤 기능은 의미가 없고, 문제 생성/채점은 커밋으로 팩트체크할 대상이 아니어서 규약과 결이 다르다. 도그푸딩은 Phase 4가 아니라 Phase 1 종료 직후로 당기되, career-forge 자신은 커밋 1개라 무의미하므로 200커밋 이상 다중 저자 외부 레포를 미리 확보한다.

## 9. 명명·라이선스 정본

레포 `career-forge` / 플러그인 `devcareer-prep` / **디렉터리 이름 상수 `.devcareer`**로 확정한다. **이 상수는 경로가 아니라 이름이며, 저장 루트 정본은 §6이 확정한 `~/.devcareer/<repo-key>/` 하나다** — 대상 레포 내부 `<repo>/.devcareer/`는 명시 동의 시에만 저장 루트로 전환된다(프라이버시 기본값과 정합). 이름 상수와 루트 해석은 `scripts/lib/store.mjs` 한 곳에 정의하고(`<repo-key>` 산출 규칙의 정본은 §6이며 store.mjs의 그 단일 함수만 이를 구현한다) 나머지 참조는 전부 그것을 경유하게 해, §6이 뜻하는 홈 기본 경로와 구현 1단계가 뜻하는 상태 디렉터리가 서로 다른 값으로 갈리는 상태를 없앤다. **슬래시 명령 접두사는 별도 선언 지점이 없고 plugin.json의 `name`에서 자동 파생되므로 정본은 `devcareer-prep:`이다** — 접두사를 짧게 만들려면 plugin.json `name` 자체를 바꾸는 수밖에 없으나, 그것은 AC-3의 5곳 일관성 검사와 README 정체성을 동시에 흔들므로 채택하지 않는다. 라이선스는 MIT(레퍼런스 플러그인 2개 모두 MIT). plugin.json의 `name`·`license`, LICENSE 파일, README 배지, 디렉터리 이름 상수 `.devcareer`, 문서 내 명령 접두사 표기의 일관성을 validate 스크립트의 검사 항목에 넣어 드리프트를 기계로 막는다.

**2. Phase 0-B: JSON Schema 세트 작성. evidence(원장: id·hash·shortHash·authorEmail·authorDate·`parents[]`·`isMerge`·`coAuthors[]`·files[]·insertions·deletions·subject·excluded/exclusionReason), career, knowledge-map, gap-report, state, config. **커밋마다 부모 해시 배열 `parents[]`를 기록하고 `isMerge = (parents.length >= 2)`를 함께 기재하며, 이 값이 머지 판정의 유일한 정본이다** — `viaMerge`나 `excluded`/`exclusionReason`으로 머지를 역추정하는 경로는 금지한다(`viaMerge`는 검사 대상이므로 그것으로 머지를 식별하면 AC-6의 머지 절이 자기충족 검사가 되고, `exclusionReason`은 머지 '제외' 설정에서만 값이 생겨 정작 규칙이 필요한 '포함' 설정에서 오라클이 비어버린다). `files[]` 항목 형태를 `{path, oldPath|null, changeType(A/M/D/R), insertions, deletions, binary, viaMerge}`로 고정하고(`viaMerge: true`는 머지 커밋의 1부모 diff로 유입된 항목 표시 — 변경량 합계·최다 변경 파일·확장자 히스토그램 등 **항목 단위 집계와 커밋 레벨 `insertions`/`deletions` 양쪽의 정량 집계에서 제외한다**), `insertions`/`deletions`가 `-`(바이너리)인 경우 숫자 0이 아니라 `binary: true`로 기록해 변경량 집계에서 제외한다. **Co-authored-by 트레일러의 P0 방침은 「원장에 기록하되 귀속 규칙은 두지 않는다」로 확정한다** — 커밋 메시지 본문의 `Co-authored-by: Name <email>` 트레일러를 파싱해 `coAuthors[]`에 원문 문자열 배열로 기록하고(부재·파싱 실패 시 빈 배열), **이 값을 저자 필터·`excluded` 판정·정량 집계에 반영하는 규칙은 P1로 명시 연기한다.** 필드를 아예 두지 않으면 페어 작업물을 단독 성과로 주장하는 경로(엣지 케이스 목록)가 원장 수준에서 관측조차 불가능해지고, 반대로 P0에서 귀속 규칙까지 넣으면 §5의 identity 다중 선택 게이트와 판정 주체가 이중화된다. 기록 전용 필드이므로 값 계약을 스키마 description에 함께 못 박는다: 「커밋 메시지 트레일러 `Co-authored-by:`의 값 원문 배열. 트레일러가 없으면 빈 배열이며, P0에서는 어떤 필터·집계에도 사용하지 않는다.」 **커밋 레벨 `insertions`/`deletions`는 `files[]` 항목 중 `viaMerge !== true` 이고 `binary !== true` 인 항목의 합으로 정의한다 — 따라서 머지 커밋의 커밋 레벨 값은 항상 0이다.** 공통 필드로 schemaVersion·generatedAt·sourceRepoHead·contentHash·`coverage{analyzed, total, traversed, period, exclusions, samplingMethod}`·`truncated{reason, dropped_commits}`, 노드 공통 필드로 evidence[]·basis(commit/inference/external/insufficient)·origin(generated/user)·locked를 정의한다. **`coverage.analyzed`/`coverage.total`은 `excluded !== true`인 커밋 기준이며, 순회한 총 커밋 수는 별도 필드 `coverage.traversed`로 기재한다** — 두 수치를 한 필드에 섞으면 `excluded: true` 커밋이 예산과 커버리지를 동시에 오염시킨다(`traversed`에는 `excluded: true` 커밋이 포함되고, 그 커밋들은 예산과 무관하게 원장에 전량 등재된다 — 모집단 정의는 구현 5단계 참조). **`coverage.traversed`는 필드 신설만으로는 아무것도 막지 못하므로 값 계약을 `evidence.schema.json`의 description에 다음 문장으로 못 박는다: 「순회한 전 커밋 수(= `excluded: true` 커밋 포함). 예산·절단의 분모로 쓰지 않으며, `analyzed` 또는 `total`을 그대로 복사한 값이 될 수 없다.」** — 값 계약이 없으면 구현이 `traversed`에 `total`(또는 `analyzed`)을 그대로 대입해도 그 값을 읽는 조항이 하나도 없어 스키마 적합성·기재율·골든 자기비교가 전부 통과하고, 이 필드를 신설해 막으려던 '순회 총계와 커버리지 분모 혼동'이 값 수준에서 그대로 재현된다. 300커밋 픽스처에서의 구체적 기대값(세 수치의 상호 관계 포함)은 구현 4단계 착수 전에 AC-21에 고정한다. `truncated`는 항상 존재하며 절단이 없으면 `{reason: "none", dropped_commits: 0}`을 기록하고, `reason`은 **`none|budget_commits` enum으로 고정한다**(바이트·파일 예산은 P0 범위에서 제외하고 P1로 내린다 — 선택 예산 K가 `max_commits` 단일 축으로만 산정되므로 다른 예산 사유를 enum에 남기면 `reason != "none"`인데 `dropped_commits == 0`인 자기모순 값이 생긴다). **`coverage.samplingMethod`는 `truncated`와 대칭으로 항상 존재하며, 절단이 발생하지 않았으면(`truncated.reason == "none"`) 고정 리터럴 `none:full-scan`을 기재하고 절단 시에만 구현 5단계의 정본 샘플링 리터럴을 그대로 기재한다.** config 스키마에서 **P0 예산 파라미터는 `max_commits` 하나이며 샘플링 비율 상수(recent/churn/even)는 사용자 조정 대상이 아니다** — 비율을 파라미터화하면 하드코딩된 `samplingMethod` 리터럴과 실제 선택 규칙이 어긋난다. **`state.schema.json`·`config.schema.json`의 모든 경로 필드는 §6·§9·AC-15가 확정한 저장 루트(기본 `~/.devcareer/<repo-key>/`, 명시 동의 시 `<repo>/.devcareer/`) 기준 상대 경로로 정의하며 절대경로를 저장하지 않는다** — 저장 루트가 이중값이면 같은 상대 경로가 두 루트를 가리켜 스테일 판정(AC-22)과 identity 집합 조회(AC-7 (a)축)가 서로 다른 파일을 정본으로 삼게 되고, 절대경로를 저장하면 공개 레포에 로컬 절대경로가 그대로 노출된다. 루트 자체는 스키마에 값으로 저장하지 않고 `scripts/lib/store.mjs`가 실행 시 해석한다. 모든 free-text 필드 description에 '(한국어로)'를 명시하고 해당 필드에 `x-freeText: true`, 원문 보존 필드에 `x-verbatim: true`, 기술 용어·고유명사 필드에 `x-termField: true` 마커를 부여해 AC-19 언어 린트의 대상 집합과 제외 집합을 스키마가 결정하게 한다.**

- 검증 영향: 스키마 파일 자체가 3단계 validator의 파싱 대상이자 이후 모든 산출물 검증의 기준이 된다. `changeType`/`oldPath`/`binary`/`truncated`/`x-freeText`가 여기서 확정되어야 AC-6·AC-7·AC-19·AC-21이 스키마 경유로 강제된다.

**5. L0 결정적 수집기 구현. 인자 배열 방식 git 호출 + 고정 프리픽스(--no-pager -c core.quotepath=false -c i18n.logOutputEncoding=UTF-8). 모든 `--numstat`/`--name-status` 호출에 `-z`를 붙여 NUL 구분 출력을 파싱하고 리네임 축약형(`a => b`, `d/{a => b}/f`)이 원장에 유입되지 않게 한다 — 리네임은 `path`/`oldPath` 두 필드로 분해하고 `changeType=R`로 기록한다. 입력: repo path, 선택된 저자 identity 목록, 범위(HEAD/--all), 머지 포함 여부**(순회 필터가 아니라 `excluded` 플래그·정량 집계 반영 여부를 결정)**, since/until, max_commits, include_diff(기본 false). 출력: evidence.json(원장) + git-facts.json(집계: 경로→모듈 매핑, 확장자 히스토그램, 기간, 최다 변경 파일, conventional-commit 타입 분포) + coverage/truncated 필드. 예산 초과 시 절단이 아니라 명시적 샘플링을 적용한다. **샘플링 모집단과 `K=min(max_commits,total)`의 `total`은 순회한 전 커밋이 아니라 `excluded !== true`인 커밋으로 한정한다**(시간 균등 버킷의 `even-range-default`가 기준으로 삼는 '선택 대상 커밋'도 같은 집합이다). **`excluded: true` 커밋은 예산과 무관하게 원장에 전량 등재하며(`files[]` 포함 — 그래야 절단이 걸린 실행에서도 AC-7의 집합 동치·(a)축과 AC-9가 관측 가능하다) `coverage.analyzed`/`coverage.total`/`truncated.dropped_commits`의 분모에는 산입하지 않는다**(순회 총계는 `coverage.traversed`가 별도로 기재한다 — 구현 2단계). 모집단을 순회 전 커밋으로 잡으면 예산을 제외 커밋이 잠식해 '있지도 않은 커버리지'를 선언하게 되고, 반대로 제외 커밋을 원장에서 빼면 머지 제외를 `--no-merges`로 구현하는 것과 같은 우회가 샘플링 경로로 재발한다. 선택 예산 K일 때 **최근 40% → 변경량 상위 40% → 시간 균등 20%** 순으로 채우되(내림, 잔여는 최근 버킷에 가산), 앞 버킷에 이미 선택된 커밋은 뒤 버킷에서 제외하고 부족분은 다음 순위 커밋으로 보충해 최종 선택 수가 정확히 K가 되게 한다. **'최근'의 기준 시각은 `authorDate`이며 동점은 `hash asc`로 타이브레이크한다(committerDate는 리베이스로 값이 바뀌므로 쓰지 않으며, `git log` 기본 출력 순서도 쓰지 않는다).** **'변경량'(nonVendoredChurn)은 `files[]` 중 `viaMerge !== true`·`binary !== true`이고 vendored/자동생성 경로(§5 기본 제외 목록 — node_modules/dist/vendor/*.lock/migrations, 및 package-lock.json·pnpm-lock.yaml·go.sum·composer.lock·poetry.lock 등 흔한 락파일)가 아닌 항목의 `insertions + deletions` 합이며(따라서 머지 커밋은 항상 0이다), 변경 파일 수가 아니다** — 변경 파일 수나 `files[]` 원합으로 읽으면 머지 커밋이 변경량 상위를 독식해 머지 유입분의 사용자 귀속이 표본 선택 경로로 되살아난다. vendored/락파일을 빼지 않으면(콜드 리뷰 실측) `chore(deps): bump ...` 같은 자동 lockfile 갱신 커밋이 churn 표본을 독식해 실제 작업 커밋이 밀려나고 `topChangedFiles[0]`이 `package-lock.json`이 된다 — 이 정의는 evidence.json의 커밋 레벨 `insertions`/`deletions`(AC-6 (i)의 대상, vendored 포함 전체 합)와는 별개의 값이며 스키마에 노출되지 않고 샘플링 입력으로만 쓰인다. 변경량 동점은 `(authorDate desc, hash asc)`로 타이브레이크하고, 시간 균등 버킷은 `[since, until]`을 등분해 각 구간의 authorDate 최소 커밋을 취한다 — **since/until이 지정되지 않으면 구간은 `[선택 대상 커밋의 최소 authorDate, 최대 authorDate]`로 하고**, 시간 균등 버킷의 보충 순위는 구간 내 `authorDate asc, hash asc`이며 구간이 소진되면 다음 구간으로 이월한다. `truncated.dropped_commits = total - K`를 채우고, `coverage.samplingMethod`에는 **다음 정본 문자열 리터럴을 한 글자도 바꾸지 않고 그대로** 기재한다 — 이 리터럴이 샘플링 규칙의 정본이며 다른 조항(AC-21, 테스트 전략 [볼륨])은 규칙을 재서술하지 않고 이 리터럴을 참조한다: `K=min(max_commits,total);ratio=recent40/churn40/even20;order=recent:(authorDate desc,hash asc),churn:(nonVendoredChurn desc);churnDef=nonVendoredChurn=sum(insertions+deletions over files[] excl. viaMerge,binary,vendoredPath);floor;remainder→recent;dedup=prior-buckets-excluded,backfill-next-rank;tie=churn:(authorDate desc,hash asc),even:[since,until] equal-split,min(authorDate);even-range-default=[min(authorDate),max(authorDate)];even-backfill=(authorDate asc,hash asc),carry-to-next-bucket`(콜드 리뷰 라운드에서 `churn:(commitLevelInsertions+commitLevelDeletions desc)` → `churn:(nonVendoredChurn desc)` + `churnDef=...` 절로 갱신 — vendored/lockfile 오염 대응. 이 리터럴 변경은 스키마 description·`scripts/lib/sampling.mjs`의 `CANONICAL_SAMPLING_METHOD_LITERAL`·`fixtures/golden/compute-sampling-golden.mjs`의 하드코딩 사본 세 곳과 함께 동기화됐다 — `fixtures/golden/PROVENANCE.md`의 "정본 리터럴 변경 이력" 참조.) **`coverage.samplingMethod`는 `truncated`와 대칭으로 항상 존재하며, 절단이 발생하지 않았으면(`truncated.reason == "none"`) 위 정본 리터럴 대신 고정 리터럴 `none:full-scan`을 기재한다** — 무조건 기재하면 전량 분석한 소형 레포의 산출물이 '있지도 않은 샘플링을 선언'하게 되고, 미절단 시 값을 비우면 AC-10의 필수 필드 기재율이 (c) **산출물 쓰기 직전 `validateInstance`로 자기 검증한다** — 구현 7단계 (a)와 같은 규약이며, 이 단계가 knowledge-map.json·gap-report.json을 쓰는 주체이므로 여기에도 명시한다(한쪽에만 적으면 이 단계의 산출물만 검증 없이 디스크에 닿는다). (d) **이 두 계층에서 `verification`이 무엇을 뜻하는지 정의한다** — L2·L3의 `basis`에는 `commit`이 없으므로(inference/external/insufficient) career의 '인용한 커밋이 그 주장을 뒷받침하는가'와 판정 대상이 다르다. 여기서 2단 팩트체크가 반증하는 것은 **(i) `inference` 노드가 나열한 근거 커밋이 그 추론을 실제로 뒷받침하는가, (ii) `external` 노드의 출처가 그 서술을 뒷받침하는가**이며, 반증 시 재생성 상한(2회)과 항목 단위 강등은 career와 동일하다(§3). 이 정의 없이 `verification`만 required로 두면 구현자가 전 노드를 `not-attempted`로 채우는 것 외에 할 수 있는 일이 없고, 그것은 집행 절차 없는 필수 계약이다.**

### 테스트 전략

- [최우선] 오염 주입 테스트(negative testing): 원장에 없는 가짜 40자 hex, 근거 없는 주장, 타 저자 커밋 인용, 마스킹 우회 시크릿을 산출물에 인위 주입하고 검증 파이프라인이 반드시 REJECT하는지 측정한다. 통과율 지표로는 FactChecker의 실효성을 원리적으로 알 수 없고 탐지율만이 유일한 측정 수단이다. **분모는 고정 40건(4종 × 10), 시행은 연속 3회, 채점은 기대 REJECT 사유 문자열 일치로 스크립트가 수행한다.** 수용선: 기계 검증 3종 3회 모두 **100%**, LLM 판정 1종 3회 최저값 **80% 이상**(절대 개수가 아니라 비율이므로 케이스 수가 바뀌어도 게이트가 유지된다). 회차 편차 20%p 초과는 완료 기준이 아니라 **지표 신뢰도 경고**이며, 케이스를 종당 20건으로 **1회에 한해** 증설한 뒤 동일 비율 기준으로 재판정한다. 증설 후에도 편차가 20%p를 넘으면 FAIL로 확정하고 FactChecker 프롬프트를 수정한다 — 증설을 근거로 재실행 최고값을 채택하는 경로는 금지한다.
- [최우선] validate-plugin 자체에 대한 negative 픽스처: `tests/fixtures-invalid/` 7케이스(필수 필드 누락 plugin.json / name≠디렉터리 SKILL.md / 1인칭 description / 깨진 JSON 스키마 / CR 혼입 텍스트 / README 배지 라이선스 불일치 / 영문 서술형 free-text)에 대해 exit 1 + 케이스 고유 오류 코드를, `tests/fixtures-valid/`의 '정상 통과해야 하는 영문 용어 필드' positive 픽스처에 대해 exit 0을 확인한다(`--negative`가 negative 케이스와 positive 픽스처를 함께 돈다). `tests/fixtures-invalid/`는 통상 스캔에서 제외되고 `--negative`가 케이스별 검사 루트를 명시 지정해 호출하며, CR 케이스는 `tests/fixtures-invalid/** -text`로 CR 바이트 보존을 사전 확인한다. 정상 레포에서 exit 0만 보면 검사 로직이 상시 빈 배열을 반환해도 게이트를 통과한다 — 이 프로젝트 최초의 검증기 자신에게도 negative testing 원칙을 대칭 적용한다.
- [최우선] 골든 픽스처 회귀: GIT_AUTHOR_DATE/COMMITTER_DATE/이름/이메일을 고정해 커밋 해시가 재현되는 픽스처 레포로 evidence.json 골든 파일 비교. 시나리오는 0커밋, 1커밋(초기 커밋, 부모 없음), 다중 저자, 봇 커밋, 한글 파일명/메시지, 공백 포함 경로, merge, 리네임, **파일 삭제**, node_modules, 가짜 API 키 포함 커밋, 바이너리 파일, **300커밋 대량 레포**.
- [git 출력 계약] 삭제 커밋의 (해시, 경로) 인용이 FAIL 나지 않는지, 리네임 커밋에서 `path`/`oldPath`가 분리 기록되는지, 바이너리 파일이 `binary: true`로 집계 제외되는지, 조회 실패 stderr 패턴의 exit 128은 인용 FAIL로·그 외 128과 129 이상만 도구 오류로 분류되는지를 픽스처로 각각 확인한다. 머지 커밋에서 `git log --numstat`은 빈 출력, `git show --numstat`은 1부모 대비 전량을 내보내는 비대칭을 픽스처로 고정 확인하고, 수집기·검증기가 동일한 1부모 diff 연산(`git diff --numstat -z M^1 M`)을 공유해 원장 `files[]`와 검증기 diff 집합이 집합 동치임을 확인한다. **과대 허용 방향만이 아니라 누락 방향도 본다** — merge 픽스처의 사이드 브랜치 커밋이 원장에 전부 존재하는지를 커밋 수 골든으로 확인한다(순회에 `--first-parent`를 쓰면 소실된다). 3분류의 두 분기는 각각 (16)옵트인 스니펫 인용 픽스처(조회 실패 128 → 인용 FAIL)와 (15)도구 오류 유발 픽스처(128/129+ → 인용 FAIL 미집계·별도 섹션)로 관측한다. 머지 해시를 인용한 정량 주장의 FAIL은 **(17) 머지 해시를 `basis: commit` 근거로 인용한 산출물 주입 케이스**(merge 픽스처 위에 인위 주입한 산출물 케이스이며 오염 스위트 40건과 별개이고 그 분모에 산입하지 않는다)로 관측한다. **(17)은 머지 포함 설정에서 실행하며**(제외 설정에서는 (a)축 FAIL로 뭉개져 basis 규칙이 평가되지 않는다), **기대 REJECT 사유 문자열이 (a)축 "제외 커밋 인용"이 아니라 `basis: commit` + 머지 해시 규칙 위반 코드와 일치할 때만 탐지로 채점한다.**
- [불변식 검증] LLM 출력의 문장 비교 회귀 테스트는 비결정성 때문에 처음부터 포기하고, 대신 불변식만 검사한다: 모든 인용 해시가 픽스처에 실존 / 타 저자 커밋 미포함 / 봇 커밋 미포함 / 시크릿 문자열 미포함 / 커버리지 메타데이터 존재 / truncated 필드 존재 / 스키마 필수 필드 충족 / 계층 ID 참조 미해결 0건.
- [정적 린트] plugin.json 스키마, 모든 SKILL.md frontmatter 필수 필드·name 중복·name↔디렉터리 일치·description 3인칭, 문서 내 상대 경로 참조 실재성, 명명·라이선스 5곳 일관성, 문서 내 슬래시 명령 접두사 ↔ plugin.json `name` 일치, 워킹 트리 CR 검사, `--lang-check` 언어 린트. 스킬 수가 늘어난 뒤에 도입하면 이미 깨진 파일들을 한꺼번에 고쳐야 하므로 Phase 0에 배치.
- [경계조건 배터리] 비-git 경로 / bare repo / worktree / detached HEAD / unborn branch / shallow clone(.git/shallow 존재) 각각에 대해 예외 중단이 아닌 명확한 안내 메시지와 정상 종료를 확인.
- [볼륨] 300커밋 픽스처에서 `max_commits=50` 고정(since/until 미지정) 시 `truncated.dropped_commits == coverage.total - K` — **분모는 순회 총계 300이 아니라 `coverage.total`(= `excluded !== true` 커밋 수)이고 `K = min(max_commits, coverage.total) = 50`이며, 픽스처가 봇·타 저자·머지 커밋을 포함하므로 `coverage.total < 300`이다. 절대값 250을 하드코딩하지 않는다(AC-21과 동일 관계식)**, 커버리지 3수치가 AC-21이 못 박은 기대값(`coverage.traversed == 300`, `coverage.total`은 픽스처 생성기가 선언한 `excluded !== true` 커밋 수, `coverage.analyzed == 50`)과 일치, 선택 집합이 **구현 5단계에 리터럴로 고정된 정본 `samplingMethod` 문자열이 규정하는 규칙** 골든과 일치, `coverage.samplingMethod` 값이 그 리터럴과 완전 일치, 2회 실행 시 동일 집합을 확인한다 — 규칙은 여기서 재서술하지 않고 리터럴을 참조한다. 500커밋급 실레포에서도 조용한 절단 없이 정상 종료하는지, --no-diff 모드와 diff 포함 모드의 컨텍스트 사용량 차이를 비교.
- [Windows 특화] pwsh 7 경로에서 실행 확인(개발자 본인 Git Bash 환경에서만 테스트하면 재현 못 하는 문제 있음). 한글 경로·공백 경로·260자 초과 경로·UNC 경로, pager 대기 미발생, `.sh` 포함 명령의 자동 bash 프리픽스 회피.
- [데이터 보존] 사용자가 career.json을 수동 편집한 뒤 재실행 → contentHash 불일치 감지 → 확인 게이트 → locked 노드 보존 확인. 강행 시 `career.json.bak` 1세대 보존 확인(AC-16과 같은 문자열 — 두 곳을 함께 유지한다). 같은 원장으로 2회 생성해 동일 사실 항목의 노드 `id`가 동일한지도 확인한다(AC-16의 재실행 안정성 기준 — 이것이 깨지면 locked 보존이 성립하지 않는다).
- [상태·스테일] career.json 생성 → 픽스처에 커밋 1개 추가 → skill-gap 실행 시 '오래된 근거' 경고가 산출물·콘솔 양쪽에 출력되는지, state.json 부재/스키마 부적합 시 예외 중단 없이 재수집 안내로 정상 종료하는지 확인.
- [프라이버시] 픽스처에 심어둔 가짜 AWS 키·private key 블록·JWT·동료 이메일이 어떤 산출물에도 노출되지 않는지 문자열 검색으로 확인. 기본 저장 위치가 홈이고 레포 내 저장 시 .gitignore 제안이 뜨는지 확인.
- [라우팅] 설치 후 실제 프롬프트 여러 개로 `/study`·`/codebase-audit`·`/handoff` 등 기존 설치 스킬과의 오발동 여부 확인. 실제 노출 접두사가 `devcareer-prep:`인지, 문서 표기와 일치하는지 확인. 충돌 증상이 '아무 일도 안 일어남'이라 배포 후 진단이 매우 비싸므로 배포 전 필수.
- [UX 실패 경로] FactChecker 2회 재시도 실패 시나리오를 인위 유발해 빈손 출력이 아니라 '근거 부족 - 미검증' 배지가 달린 부분 출력이 나오는지 확인.
- [언어] 전 산출물 free-text 필드(`x-freeText: true`)에 대한 `--lang-check` 기계 린트 — 판정 단위는 필드 값이며, 공백 구분 토큰 4개 이상인 서술형 값에 한글이 0자면 FAIL. 커밋 subject·파일 경로·`x-verbatim` 필드·`x-termField` 필드(기술 용어·고유명사)·코드 블록은 제외하고, `tests/fixtures-valid/`의 영문 용어 필드 positive 픽스처로 오탐을 회귀로 잡는다. `origin: "user"` 노드는 노드 단위로 검사에서 제외하며, 그 제외가 정확히 좁게 작동하는지를 `origin` 값 하나만 다른 픽스처 쌍(`tests/fixtures-valid/gap-report.json` ↔ `tests/fixtures-invalid/20-gap-report-generated-english/`)으로 관측한다. 전역 규약상 언어 누수는 스타일 문제가 아니라 버그다.
- [동시성·IO] 동시 세션 2개가 같은 저장 디렉터리에 쓰는 경합, 읽기 전용 디렉터리, 디스크 가득참 상황에서 부분 쓰기로 상태 파일이 손상되지 않는지(temp→rename) 확인.

### 엣지 케이스

- 커밋 0개 / unborn branch — 지금 이 레포가 거의 그 상태다. 예외 중단이 아니라 명확한 안내 후 정상 종료해야 한다.
- 초기 커밋(부모 없음) — `HEAD~1` 기준 diff가 실패한다. 빈 트리 대비로 처리.
- git 레포가 아닌 경로 / bare repo / linked worktree / detached HEAD — 각각 다른 실패 경로를 만든다.
- shallow clone(`.git/shallow` 존재) — 히스토리가 잘려 있는데 완전한 척 분석된다. 감지 후 커버리지에 명시.
- 대형 히스토리(500커밋급) — `git log -p`가 수 MB. 예산 상한 초과를 truncated 필드로 일급 처리.
- 머지 커밋 위주 레포 — 머지 제외 시 커밋 수가 급감(실측 134→97). 포함 여부를 사용자에게 확정받고 기록.
- 동일인 저자 별칭 분산(회사 이메일/개인 이메일/GitHub noreply, LeeJungGu vs jaewon_j 류) — 다중 선택 게이트 필수.
- 봇 커밋(dependabot, github-actions[bot], `[bot]` 패턴) — 기본 제외 후 사용자 조정 허용.
- vendored/자동생성 경로(node_modules, dist, vendor, *.lock, migrations) — 기여도 합산 오염원. 기본 제외.
- **파일 삭제 커밋** — 삭제 커밋의 트리에는 그 경로가 없어 `git cat-file -e <sha>:<path>`가 exit 128로 실패하는데 `--numstat`은 그 경로를 보고한다. 원장이 만든 (해시, 경로) 쌍이 자기 검증기에서 오탐 FAIL 나며, "레거시 모듈을 제거했다"는 참인 경력 서술이 '근거 부족'으로 강등된다. 경로 실존성은 트리가 아니라 diff 집합 대조로 판정한다.
- 리네임 다수 / 바이너리 diff / Git LFS 포인터 파일 — 변경량 통계를 왜곡한다. `--numstat`의 리네임 축약형(`a => b`, `src/{old => new}/m.txt`)이 `-z` 없이 그대로 원장에 들어가면 인용 검증 전량 실패 + 존재하지 않는 디렉터리(`{old`)가 모듈로 집계된다. 바이너리의 `-` 값은 0이 아니라 `binary: true`로 기록.
- 한글 커밋 메시지·한글 파일명 — core.quotepath 기본값에서 `\355\225\234` 옥탈 이스케이프, CP949 인코딩 혼입.
- 경로에 공백 포함 / 260자 초과 / UNC 경로 — Windows 특유 실패.
- 워킹 트리 CRLF 혼입 — .gitattributes는 스테이징 시 정규화만 하므로 `git status`는 깨끗한데 로컬 파일이 깨진 상태가 된다.
- 커밋 타임존 오프셋 미처리 — 재직/프로젝트 기간이 하루 단위로 틀어진다. 날짜는 사실 주장이므로 이것도 할루시네이션이다.
- 빈 커밋 메시지 / force-push로 재작성된 히스토리 — 인용한 해시가 나중에 사라질 수 있다.
- 커밋 메시지 신호 품질 극단 차이 — 정제된 Conventional Commits 레포와 `만월경 , Syste.out 제거` 수준 레포가 공존한다. 메시지만으로 경력이 안 나오는 경우 신뢰도를 낮춰 보고.
- Co-authored-by 트레일러 — 페어 작업물을 단독 성과로 주장하게 된다. **P0 방침은 「원장 `coAuthors[]`에 기록만, 저자 필터·`excluded` 판정·정량 집계 반영은 P1」로 확정했다(구현 2단계)** — 트레일러를 무시해 필드조차 두지 않는 선택도, P0에서 귀속 규칙을 도입하는 선택도 아니다.
- diff 내 시크릿·PII(AWS 키, `-----BEGIN ... PRIVATE KEY-----`, JWT, `password=`, 동료 이메일) — 마스킹 후에도 완전 제거는 불가.
- 사용자가 수동 편집한 상태에서 재실행 — contentHash 불일치 감지 없이는 편집분이 유실된다.
- 동시 세션 2개가 같은 저장 디렉터리에 쓰기 / 디스크 가득참으로 부분 쓰기 / 읽기 전용 디렉터리.
- FactChecker 2회 재시도 후에도 미승인 — 빈손 출력이 아니라 항목 단위 '근거 부족' 배지로 강등.
- 오프라인(웹 검색 불가) 상태에서 외부 출처 인용이 필요한 지식 노드 — allow-list 참조 실패 시 `insufficient` 폴백.
- 사용자가 원격 GitHub URL을 입력 — P0 미지원이므로 명확한 안내와 수동 clone 대안 제시.
- 상위 산출물 생성 시점의 HEAD와 현재 HEAD가 다름(스테일 근거) — 하위 명령 실행 시 state.json을 읽어 경고하고 계속/중단 선택 제시. state.json 부재·스키마 부적합도 예외 중단 없이 재수집 안내로 정상 종료.

### 리스크

- **(qa_specialist (architect·senior_developer 동의), high)** 커밋 해시 할루시네이션 — GitExtractor가 LLM이면 40자 hex가 '생성물'이 되고, 사람 눈으로 검증 불가하며 FactChecker도 LLM이라 실존 여부를 판단할 수 없다. 인용 규약이 통째로 무력화되는데 겉보기 산출물은 완벽해 보이는 조용한 실패다. — 수집을 LLM 없는 결정적 스크립트로 재정의하고 evidence.json 원장을 만든다. LLM은 해시를 '쓰지' 않고 원장 ID를 '고르기'만 한다. verify-evidence.mjs가 원장 포함 여부 + git 객체 실존성 + diff 집합 대조를 기계로 검사한다.
- **(architect·senior_developer·qa_specialist (전원 합의), high)** 컨텍스트 폭발과 조용한 절단 — 실측상 100커밋 full diff는 약 25만 토큰(pass-api-be 134커밋 numstat만 51KB, 커밋당 평균 diff 약 10KB). 상한 없이 넣으면 중간이 잘리고 사용자는 '전체를 분석했다'고 믿는다. — 예산 상한(**P0는 커밋 수 단일 축 — 바이트 상한·파일 수 상한은 P1로 연기**)과 구현 5단계의 정본 `samplingMethod` 리터럴이 규정하는 명시적 샘플링을 두고, coverage/truncated를 일급 출력 필드로 강제한다. 선언에 그치지 않도록 AC-21(300커밋 픽스처 + 골든 비교 + 결정성)로 게이트한다 — 이 게이트가 없으면 `slice(0, max)` 구현이 전 AC를 통과한다. --no-diff 모드를 P0 기본값으로.
- **(senior_developer·qa_specialist, high)** 저자 귀속 오염 — 멀티 저자 레포에서 author 필터를 놓치면 팀 전체 작업이 사용자 경력에 들어간다. 실측상 pass-api-be는 --all 325 vs HEAD 134커밋이고 사용자 본인 커밋은 9개뿐이었다. '해시를 인용했지만 그 커밋이 내 것이 아닌' 상태 — 규약을 지키면서도 허위 경력이 생산된다. 면접 자리에서 사용자를 곤란하게 만드는 실질 피해. — 실행 초입에 `git shortlog -sne` 후보 제시 → 사용자 다중 선택(추측 금지) → config.json 저장. 범위(HEAD/--all)·머지 포함 여부·기간을 함께 확정하고 산출물 최상단에 기록. 봇 계정과 vendored 경로 기본 제외.
- **(qa_specialist (architect 병목 지적과 결합), high)** FactChecker의 구조적 무력함 — 같은 모델 계열이 자기 산출물을 검증하면 자기일관성 편향으로 통과율이 비정상적으로 높다. 더 나쁜 건 REJECT 시 동작이 SPEC에 정의돼 있지 않아 무한 재생성 루프이거나 그냥 통과로 귀결된다는 점이다. — 2단 분리(기계 1단 + LLM 2단), 프롬프트를 '검증하라'가 아닌 '반증하라'로 적대적 작성, 생성 측 추론 과정을 입력에서 제외해 독립성 확보.
