# ■ 구현자 착수 전 체크리스트 (이 문서에서 가장 중요한 부분)

아래 세 블록은 **읽고 넘어가는 참고 자료가 아니라 게이트다.** 각 항목은 "해당 단계 착수 전에 spec.md 문장을 닫는다"가 완료 조건이며,
닫지 않고 진행하면 괄호 안의 재작업 비용이 확정적으로 발생한다.

## □ 게이트 A — 구현 2단계(Phase 0-B, JSON Schema 세트 확정) 착수 전

> 여기를 지나면 `schemas/evidence.schema.json`이 굳고, 이후 수정은 **골든 evidence.json 전량 + 그 위에 쌓인 career/knowledge-map 골든까지 재생성 대상**이 된다.

- [ ] **A-1. `truncated` 불변식을 양방향으로 만든다.** 현재 AC-6은 「`reason != "none"` → `dropped_commits > 0`」 한 방향만 강제한다. 역방향 「`dropped_commits > 0` → `reason != "none"`」과, 「`reason == "none"` ⟺ `samplingMethod == "none:full-scan"`」 동치를 **픽스처 종류와 무관한 전역 불변식**으로 AC-6에 추가한다. (→ [R6-Major-2])
- [ ] **A-2. AC-6에 (iii)·(iv) 절을 추가해 (ii)의 공허 통과를 막는다.** (iii) 「`isMerge === (parents.length >= 2)`」를 괄호 정의가 아니라 **기계 검사 불변식**으로 격상. (iv) 「merge 픽스처의 원장에 `isMerge === true`인 커밋이 최소 1건 존재하고 그 `parents.length == 2`」. 이 두 절이 없으면 `%P`를 빼먹어 전 커밋 `parents: []`가 된 구현에서 (ii)가 공허하게 PASS 하고, **round 5·6에 걸쳐 닫은 자기충족이 그대로 부활한다.** (→ [R6-Major-3])
- [ ] **A-3. `coverage.traversed`의 값 계약을 스키마 description에 못 박는다.** 「순회한 전 커밋 수(= `excluded: true` 포함). `analyzed`/`total`과 같은 값이 될 수 없으며 예산·절단 분모로 쓰지 않는다」. 필드만 있고 값 계약이 없으면 구현이 `total`이나 `analyzed`를 그대로 복사해도 어떤 AC도 읽지 않는다. (→ [R6-Major-1], 기대값 자체는 게이트 B의 B-2)
- [ ] **A-4. (미검사 영역이지만 스키마에 걸린다) 저장 위치 이중값을 하나로 확정한다.** `~/.devcareer/<repo-key>/`(§6, AC-15) vs 상태 디렉터리 `.devcareer/`(§9, 구현 1단계). `state.schema.json`·`config.schema.json`의 경로 필드가 여기에 달려 있다. **5라운드 연속 미해결 관찰이며 이번에도 검사되지 않았다.**
- [ ] **A-5. (미검사 영역이지만 스키마에 걸린다) Co-authored-by 트레일러의 P0 처리 방침을 결정한다.** 엣지 케이스 목록에는 있으나 구현 5단계 수집 규칙과 어떤 AC에도 없다. 원장 커밋 필드(공동 저자 배열)를 추가할지, 「P0 미지원」을 명시할지를 **스키마 확정 전에** 정한다. 저자 정체성 게이트(§5)의 실효성과 직결된다.

## □ 게이트 B — 구현 4단계(Phase 0-D, 픽스처·골든 생성) 착수 전

> 여기를 지나면 `fixtures/golden/`이 굳고, 잘못된 규칙이 골든에 박히면 **골든이 곧 규칙**이 되어 이후 어떤 AC도 그것을 반증하지 못한다.

- [ ] **B-1. AC-21 (a)와 테스트 전략 [볼륨]의 `250` 하드코드를 제거한다.** 이번 라운드 수정이 「300커밋 픽스처는 봇·타 저자·머지 커밋을 포함하도록 구성」을 요구했고 구현 5단계가 `total`을 `excluded !== true` 커밋으로 한정했으므로, **정확히 구현된 수집기의 `dropped_commits`는 250이 아니다.** 두 곳 모두 「=250」을 지우고 `total = coverage.total`(= `excluded !== true` 커밋 수)임을 명시하거나, 픽스처를 「`excluded !== true` 커밋 300건 + excluded 커밋 별도 N건」으로 재정의한다. **현 상태로는 올바른 구현이 AC-21에서 FAIL 한다.** (→ [R6-Major-4])

- [ ] **B-4. 리네임·삭제 커밋의 `path`/`oldPath` 기대값을 픽스처 정의에 하드코딩한다.** 골든이 아니라 **`fixtures/make-fixture.mjs`가 선언한 값** 또는 스펙 본문의 값과 대조하는 조항을 AC-7 또는 AC-17에 넣는다. 구현 5·6단계가 머지 규칙과 3분류를 `scripts/lib/git.mjs`에 단일 구현해 공유하도록 못 박은 결과, **AC-7의 집합 동치는 같은 함수의 두 호출 비교라 `git.mjs` 자체의 `-z` 파싱 오류를 원리적으로 잡지 못한다.** (→ [R6-Minor-2])
- [ ] **B-5. (반영 완료 항목 — 골든 생성 시 실행 조건 확인)** (17) 케이스는 **머지 포함 설정**에서 실행하고, 기대 REJECT 사유가 (a)축 "제외 커밋 인용"이 아니라 `basis: commit` + 머지 해시 규칙 위반 코드여야 탐지로 채점한다. 네 곳(AC-7 / 구현 4단계 / 구현 6단계 / 테스트 전략)에 동일 문장으로 들어가 있음을 확인했다. 골든·러너 구현 시 이 조건을 코드로 옮긴다.
- [ ] **B-6. (미검사 영역) AC-1의 "의존성 0"과 AC-12의 "스키마 레벨 강제"의 긴장을 해소한다.** JSON Schema 인스턴스 검증기를 자작해야 하는데 그 산출물이 범위·구현 단계 어디에도 없다. 3단계(Phase 0-C)에서 만들지, 4단계 이전에 별도로 세울지를 정한다. **5라운드 연속 미해결 관찰이며 이번에도 검사되지 않았다.**

## 2. AC 자기참조 절단 감사 — **절단됨 (selfReferenceBroken: true)**

핵심 사고 실험(`viaMerge: true` 부여 완전 누락)을 개정본 AC-6에 절 단위로 통과시킨 결과:

- [스키마 적합성 절] PASS(못 잡음) — 필드 존재만 보므로 `viaMerge: false`로 채우면 통과
- [(i) 커밋 레벨 == non-`viaMerge`·non-`binary` 합] PASS(못 잡음) — 필터가 항등 필터가 되어 3,200 == 3,200. **스펙도 이 자기충족을 명시적으로 인정하고 있다**
- **[(ii) `isMerge === true` → 전 항목 `viaMerge: true` + 커밋 레벨 0] FAIL(잡는다)** — 판정 오라클 `parents[]`/`isMerge`는 `%P`에서 오고 files[]는 `--numstat`에서 오므로 **입력 경로가 다르다.** (ii-a) `viaMerge: true` 0건, (ii-b) 3,200 ≠ 0 두 갈래 모두에서 독립 FAIL

결정적이었던 것은 절 분리 자체가 아니라 **구현 2단계의 역추정 금지 문장**이다. 이 문장이 없으면 구현자가 `isMerge`를 `viaMerge`에서 역산해 (ii)를 자기충족으로 되돌릴 수 있었다. 오라클 자체의 신뢰성도 과소보고(AC-7 (17) 케이스)·과대보고(AC-7 「참인 인용의 오탐 0건」) 양방향으로 얕게나마 고정돼 있다.

**다만 이 절단은 AC-6 단독으로는 완결되지 않는다** — (ii)의 비공허성이 AC-6 안에서 보장되지 않아, `parents[]`가 통째로 비면 (ii)가 공허 PASS 한다. 이것이 [R6-Major-3]이며 게이트 A-2다.

## Major

### [R6-Major-1] `coverage.traversed`가 신규 필드인데 값을 읽는 조항이 하나도 없어, 이 필드를 신설해 막으려던 '순회 총계와 커버리지 분모 혼동'이 값 수준에서 그대로 재현된다

> 성격: round 5 수정이 만든 결함(필드는 만들었으나 오라클을 만들지 않음). **게이트: A-3(스키마 계약) + B-2(AC-21 기대값).**

**왜 문제인가.** AC-6은 스키마 적합성(필드 존재)만, AC-10은 기재율 100%(존재)만, AC-21은 「순회 총계는 `coverage.traversed`에 별도 기재되므로 (a)의 분모와 섞이지 않아야 한다」고 말할 뿐 **기대값을 주지 않는다.**

**실패 시나리오.** 300커밋 픽스처(excluded 60건, total=240, analyzed=50)에서 구현이 `traversed`를 `total`과 같은 240으로(또는 `analyzed`와 같은 50으로) 채운다 → AC-6·AC-10·AC-21 (a)(b)(c) 어느 절도 이 값을 읽지 않아 **전부 PASS.** 골든 evidence.json 비교도 자기 출력 스냅샷이라 PASS.

**수정.** AC-21에 「`coverage.traversed == 300`, `coverage.total == excluded !== true 커밋 수`, `coverage.analyzed == K == 50`」을 기대값으로 못 박고, `evidence.schema.json`의 `traversed` description에 「`analyzed`/`total`과 같은 값이 될 수 없으며 예산·절단 분모로 쓰지 않는다」를 넣는다.

### [R6-Major-2] `truncated` 불변식이 한 방향뿐이라 '절단해 놓고 절단 없음이라 선언'하는 조합을 아무 절도 잡지 못한다

> 성격: 이전부터 존재(round 5가 추가한 불변식의 미완성분). **게이트: A-1.**

**왜 문제인가.** AC-6이 강제하는 것은 「`reason != "none"` → `dropped_commits > 0`」 하나뿐이고 역방향이 없다.

**실패 시나리오.** 300커밋/`max_commits=50` 실행에서 샘플링은 정확히 하되 `truncated = {reason: "none", dropped_commits: 190}`, `coverage.samplingMethod = "none:full-scan"`으로 기재한다 →
불변식은 **전건 거짓이라 PASS**, AC-6의 미절단 확인 항목은 '절단이 발생하지 않은 픽스처'로 스코프가 한정돼 적용 대상이 아니고, AC-21 (a)는 `dropped_commits == total - K`만 보므로 PASS, (b) 골든 자기 비교 PASS, AC-10 기재율 PASS.
유일한 잠재 관측점 AC-21 (c)는 적용 조건 「절단이 발생한 픽스처에 한해」가 **픽스처 구성 기준인지 자기선언 `truncated.reason` 기준인지 미정의**여서, 자기선언으로 읽으면 (c)도 적용되지 않는다.

§4가 "구조적으로 불가능하게" 만들겠다던 **조용한 절단이 정확히 이 조합이다.**

**수정.** ① 「`dropped_commits > 0` ⟺ `reason != "none"`」 양방향 불변식, ② 「`reason == "none"` ⟺ `samplingMethod == "none:full-scan"`」 **전역(픽스처 무관)** 불변식을 AC-6에 넣고, ③ AC-21 (c)의 적용 조건을 **'픽스처 구성 기준'**으로 명시한다.

### [R6-Major-3] AC-6 (ii)의 비공허성이 AC-6 안에서 보장되지 않고 `parents[]`의 정확성도 AC-6이 검사하지 않아, 이번에 끊은 자기충족이 `%P` 누락 하나로 부활한다

> 성격: round 6 수정이 만든 결함(오라클을 도입했으나 오라클 자체를 검사하지 않음). **게이트: A-2(+ C-1 재확인).**

전역 오라클은 AC-7 (17) 케이스 하나뿐인데 **그것은 구현 6단계에서야 관측되고 0-D 이연 대상**이므로, **구현 5단계 완료 게이트 시점에는 오라클이 없다.**

**수정.** AC-6에 (iii) 「`isMerge === (parents.length >= 2)` 불변식」, (iv) 「merge 픽스처의 원장에 `isMerge === true`인 커밋이 최소 1건 존재하고 그 `parents.length == 2`」를 추가한다.

### [R6-Major-4] AC-21과 테스트 전략 [볼륨]의 `250` 하드코드가 이번 수정과 정면 충돌해, 정확히 구현된 수집기를 FAIL시킨다

> 성격: round 5 수정이 만든 결함(자기충족의 **반대 방향** — 과대 탐지). **게이트: B-1.**

**왜 문제인가.** AC-21 (a)와 테스트 전략 [볼륨] 두 곳 모두 `truncated.dropped_commits == total - K`를 요구하면서 괄호로 「=250」을 못 박았다. 그런데 같은 AC-21이 이번에 「300커밋 픽스처는 **봇·타 저자·머지 커밋을 포함하도록 구성**」을 요구했고, 구현 5단계가 `total`을 `excluded !== true` 커밋으로 한정했다. 봇·타 저자 커밋은 정의상 `excluded: true`이므로 **`total < 300`이고 `dropped_commits`는 250이 아니다.**

**수정.** 「=250」을 지우고 `total = coverage.total`임을 명시하거나, 픽스처를 「`excluded !== true` 커밋 300건 + excluded 커밋 별도 N건」으로 재정의한다. 두 곳(AC-21, 테스트 전략 [볼륨])을 **동시에** 고쳐야 한다.

# ■ 미검사 영역 — 「검증됨」이 아니라 「미검사」다
